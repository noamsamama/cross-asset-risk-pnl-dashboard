# Cross-asset risk & P&L dashboard

FastAPI backend (`backend/app/`) + React/TypeScript/Vite frontend (`frontend/src/`). One Docker image serves both on Render.

## Commands
- Setup: `python3.12 -m venv .venv && .venv/bin/pip install -r backend/requirements.txt`, then `cd frontend && npm ci`
- API: `cd backend && ../.venv/bin/uvicorn app.main:app --reload` (port 8000)
- Frontend: `cd frontend && npm run dev` (port 5173, views at `/P&L` and `/Risk`)
- Verify before finishing (same as CI):
  - `cd backend && ../.venv/bin/python -m pytest`
  - `cd frontend && npm run format:check && npm run lint && npm run build`

## Layout
- `data.py`: CSV loading, normalization, data-quality issues, trades + FX (as-of date = latest FX date)
- `pnl.py`: sensitivity-explained P&L; `risk.py`: risk aggregation and native/USD reconciliation
- `main.py`: endpoints `/api/hello`, `/api/trades`, `/api/pnl`, `/api/risk`

## Rules
- IMPORTANT: real extracts live in `data/` (gitignored and dockerignored). Never commit, print or copy them. `example_data/` is synthetic and regenerated by `notebooks/generate_example_data.ipynb`.
- P&L formulas, sign conventions and units are documented in README ("Explained P&L methodology", "Risk and data controls"). Any formula change must update that section and add a test with a hand-computed value.
- Unusable data fails loudly: invalid input raises `ValueError` -> 503 with an actionable message. Don't silently drop or zero-fill; usable-but-suspicious records become amber `QualityIssue`s.
- Don't sum non-additive metrics (Duration) or net notionals across products.
- Every push to `main` deploys to Render.
